## 📌 1. ภาพรวมโปรเจกต์ (Project Overview)

**My Task Manager CLI** คือแอปพลิเคชันจัดการรายการสิ่งที่ต้องทำ (To-Do List / Task Management) ที่ทำงานผ่านหน้าต่างเทอร์มินัล (Command-Line Interface) พัฒนาด้วยภาษา Python โดยได้รับการออกแบบมาเพื่อเป็นสื่อการเรียนรู้สำหรับ**นักศึกษาชั้นปีที่ 2** ในการยกระดับทักษะจากการเขียนสคริปต์ไฟล์เดียว (Single-file Script) ไปสู่การสร้างซอฟต์แวร์ตามหลักวิศวกรรมซอฟต์แวร์มาตรฐานสากล

### 🌟 จุดเด่นและแนวคิดหลักในการเรียนรู้
- **การจัดโครงสร้างแบบแยกส่วน (Modular Architecture):** แยกความรับผิดชอบของแต่ละโมดูลอย่างชัดเจนตามหลักการ **Separation of Concerns (SoC)**
- **การเขียนโปรแกรมเชิงป้องกัน (Defensive Programming):** ประยุกต์ใช้บล็อก `try...except` และการตรวจสอบความถูกต้องของข้อมูล (Input Validation) เพื่อป้องกันไม่ให้โปรแกรมหยุดทำงานกะทันหันเมื่อผู้ใช้ป้อนข้อมูลผิดพลาด
- **การบันทึกข้อมูลอย่างถาวร (Data Persistence):** จัดเก็บและดึงข้อมูลงานในรูปแบบ JSON ผ่านไฟล์ `data/tasks.json` พร้อมระบบรับมือกรณีไฟล์สูญหายหรือข้อมูลเสียหาย
- **การฝึกฝนใช้งาน Debugger ใน VS Code:** รองรับการทำ Breakpoint, Step Over, Step Into และตรวจดูค่าตัวแปรแทนการใช้คำสั่ง `print()` เพียงอย่างเดียว
- **พร้อมสำหรับการส่งงานผ่าน Git & GitHub:** จัดโครงสร้างไฟล์และ `.gitignore` ถูกต้องตามมาตรฐาน PEP 8

## 🏗️ 2. สถาปัตยกรรมระบบและการออกแบบ (System Architecture)

โปรเจกต์นี้ใช้สถาปัตยกรรมแบบแบ่งชั้น (Three-Tier Architecture) โดยแต่ละโมดูลมีหน้าที่และความรับผิดชอบแยกจากกันโดยอิสระ:

```mermaid
graph TD
    User([👤 ผู้ใช้งาน / Terminal]) <--> Main[main.py<br><b>Presentation Layer (ชั้นติดต่อผู้ใช้)</b><br>แสดงเมนู CLI & ตรวจสอบอินพุต]
    Main <--> Logic[src/task_logic.py<br><b>Business Logic Layer (ชั้นตรรกะระบบ)</b><br>เพิ่ม ลบ แก้ไข กรอง และค้นหางาน]
    Main <--> Data[src/task_data.py<br><b>Data Access Layer (ชั้นเข้าถึงข้อมูล)</b><br>ฟังก์ชัน load_tasks / save_tasks]
    Data <--> JSON[(data/tasks.json<br><b>Storage Layer (ชั้นจัดเก็บข้อมูลถาวร)</b><br>ไฟล์ข้อมูล JSON)]
```

### หน้าที่และความรับผิดชอบของแต่ละส่วน (Module Responsibilities):
1. **Presentation Layer (`main.py`):**
   - ควบคุมการทำงานของโปรแกรมหลัก (Main Interactive Loop)
   - แสดงผลเมนูและรับข้อมูลคำสั่งจากผู้ใช้
   - ตรวจสอบและแปลงชนิดข้อมูล เช่น การแปลง String เป็น Integer พร้อมดักจับข้อผิดพลาด `ValueError`
   - จัดการสัญญาณปิดระบบฉุกเฉิน `KeyboardInterrupt` (Ctrl+C) ให้บันทึกข้อมูลก่อนออกจากโปรแกรม
2. **Business Logic Layer (`src/task_logic.py`):**
   - บรรจุฟังก์ชันตรรกะการประมวลผลงาน เช่น การคำนวณหมายเลข ID อัตโนมัติ, การเพิ่มงาน, การปรับสถานะเสร็จสิ้น, การลบงาน และการค้นหาคำสำคัญ
   - เป็นอิสระจากชั้นบันทึกไฟล์ (ไม่มีคำสั่งอ่าน/เขียนไฟล์ภายในโมดูลนี้)
3. **Data Access Layer (`src/task_data.py`):**
   - รับผิดชอบการอ่านและเขียนไฟล์ `data/tasks.json` เพียงจุดเดียวในระบบ
   - มีกลไกสร้างโฟลเดอร์อัตโนมัติหากยังไม่มี (`os.makedirs`)
   - ป้องกันข้อผิดพลาดกรณีไฟล์ไม่มีอยู่ หรือเนื้อหา JSON เสียหาย (`json.JSONDecodeError`)

## 🚀 4. การติดตั้งและเริ่มต้นใช้งาน (Installation & Getting Started)

### ความต้องการของระบบ (Prerequisites)
- **Python 3.8 ขึ้นไป** (ตรวจสอบด้วยคำสั่ง `python --version`)
- โปรแกรม **Visual Studio Code (VS Code)** (แนะนำ) พร้อมติดตั้งส่วนขยาย Python Extension
- ระบบควบคุมเวอร์ชัน **Git**

### ขั้นตอนการรันโปรเจกต์ (Step-by-Step)

1. **โคลนคลังโค้ดหรือดาวน์โหลดไฟล์:**
   ```bash
   git clone https://github.com/Supakorn231/633021103-2_sec2_Script_Programming_2026.git
   cd 633021103-2_sec2_Script_Programming_2026/<โฟลเดอร์ week 7>/my-task-manager
   ```

## 💻 5. คู่มือการใช้งานและเมนูคำสั่ง CLI (Usage & Walkthrough)

เมื่อเปิดโปรแกรม `main.py` ระบบจะโหลดข้อมูลเก่าจากไฟล์ขึ้นมา และแสดงเมนูดังนี้:

```text
Welcome to Task Manager CLI!
Loading existing tasks from storage...

==================================
        TASK MANAGER CLI          
==================================
  1. Add New Task
  2. List All Tasks
  3. List Pending Tasks
  4. List Completed Tasks
  5. Search Tasks by Keyword
  6. Mark Task as Completed
  7. Delete Task
  8. Save and Exit
```

### รายละเอียดตัวเลือกในเมนู:

| หมายเลขเมนู | ชื่อคำสั่ง | รายละเอียดการทำงาน | ข้อมูลนำเข้าที่ต้องการ | การป้องกันข้อผิดพลาด |
| :---: | :--- | :--- | :--- | :--- |
| **1** | **Add New Task** | เพิ่มงานใหม่เข้าระบบ | ข้อความบรรยายงาน และระดับความสำคัญ (`Low`, `Medium`, `High`) | ปฏิเสธข้อความว่าง; หากป้อนระดับความสำคัญไม่ถูกต้องจะปรับเป็น `Medium` ให้อัตโนมัติ |
| **2** | **List All Tasks** | แสดงรายการงานทั้งหมดในรูปแบบตาราง | ไม่มี | หากไม่มีงานจะแสดงข้อความแจ้งเตือน `[Empty]` อย่างสุภาพ |
| **3** | **List Pending Tasks** | แสดงเฉพาะงานที่ยังค้างอยู่ (ยังไม่เสร็จ) | ไม่มี | แสดงผลเฉพาะงานที่มีสถานะเป็น `[PENDING]` |
| **4** | **List Completed** | แสดงเฉพาะงานที่เสร็จสิ้นเรียบร้อยแล้ว | ไม่มี | แสดงผลเฉพาะงานที่มีสถานะเป็น `[DONE]` |
| **5** | **Search Tasks** | ค้นหางานด้วยคำสำคัญ (ไม่คำนึงถึงตัวพิมพ์เล็ก-ใหญ่) | ข้อความคำค้นหา (Keyword) | ปฏิเสธคำค้นหาที่ว่างเปล่า |

| **7** | **Delete Task** | ลบงานออกจากระบบ พร้อมถามยืนยันก่อนลบ | หมายเลข Task ID และกดยืนยัน `y` | ยกเลิกการลบทันทีหากผู้ใช้ไม่พิมพ์ยืนยัน `y` |

## 🛡️ 6. การเขียนโปรแกรมเชิงป้องกันและการจัดการข้อผิดพลาด (Defensive Programming)

หัวใจสำคัญของการเรียนการสอนในสัปดาห์ที่ 7 คือ **การเขียนโค้ดที่คาดการณ์ข้อผิดพลาดล่วงหน้า (Defensive Programming)** เพื่อไม่ให้ระบบล่มหรือหยุดทำงานเมื่อเผชิญสถานการณ์ที่ไม่คาดคิด

### แผนผังกลไกการรับมือข้อผิดพลาด (Exception Handling Flow):

```mermaid
graph LR
    subgraph จุดที่อาจเกิดข้อผิดพลาด
        E1[ผู้ใช้ป้อนตัวอักษรในช่อง ID]
        E2[ผู้ใช้ป้อนเลข ID ติดลบ]
        E3[ไฟล์ tasks.json เสียหายจากภายนอก]
        E4[โฟลเดอร์ data หรือไฟล์ยังไม่เคยถูกสร้าง]
        E5[ผู้ใช้กด Ctrl+C เพื่อบังคับปิดโปรแกรม]
    end

    subgraph กลไกป้องกันในโค้ด
        E1 --> M1[try-except ValueError]
        E2 --> M2[ตรวจสอบค่าและ raise ValueError]
        E3 --> M3[try-except json.JSONDecodeError]
        E4 --> M4[os.makedirs และ os.path.exists]
        E5 --> M5[try-except KeyboardInterrupt พร้อม Save อัตโนมัติ]
    end
```

### ตารางแจกแจงกรณีข้อผิดพลาดและการจัดการ (Exception Matrix):

| สถานการณ์ | ชนิด Exception | จุดที่ดักจับในโค้ด | ผลลัพธ์และการทำงานของโปรแกรม |
| :--- | :--- | :--- | :--- |
| ป้อนค่า `"abc"` ในช่องรับ Task ID | `ValueError` | `prompt_task_id()` ใน `main.py` | แสดงข้อความเตือนให้ระบุตัวเลข แล้วพากลับสู่เมนูหลักโดยโปรแกรมไม่แครช |
| ป้อนค่าติดลบ เช่น `"-2"` ในช่อง ID | Logic Validation | `prompt_task_id()` ใน `main.py` | ตรวจพบค่า `<= 0` แจ้งเตือนว่า Task ID ต้องเป็นจำนวนเต็มบวก |
| ไฟล์ `tasks.json` เสียหายหรือรูปแบบผิด | `json.JSONDecodeError` | `load_tasks()` ใน `src/task_data.py` | แจ้งเตือนบรรทัดที่พัง แล้วเริ่มต้นระบบด้วยลิสต์ว่างเพื่อให้โปรแกรมทำงานต่อได้ |
| โฟลเดอร์ `data/` ยังไม่มีอยู่จริง | `FileNotFoundError` | `src/task_data.py` | ฟังก์ชันจะสร้างโฟลเดอร์ให้อัตโนมัติ (`os.makedirs(..., exist_ok=True)`) |
| ผู้ใช้กดปุ่ม `Ctrl + C` ขณะรันโปรแกรม | `KeyboardInterrupt` | ลูปหลักใน `main.py` | ระบบจะดักจับสัญญาณและทำการบันทึกข้อมูลฉุกเฉินลงไฟล์ก่อนปิดระบบอย่างปลอดภัย |

## 🐞 7. คู่มือการใช้งาน VS Code Interactive Debugger

การตรวจหาข้อผิดพลาดด้วย Debugger ในโปรแกรม VS Code เป็นทักษะสำคัญที่นักศึกษาชั้นปีที่ 2 ต้องใช้งานได้อย่างคล่องแคล่ว เพื่อทดแทนการใส่ `print()` ในโค้ด

### ปุ่มลัดที่สำคัญในการควบคุม Debugger:
- **`F5` (`Continue`):** สั่งรันโปรแกรมต่อเนื่องไปจนกว่าจะพบ Breakpoint ถัดไป
- **`F10` (`Step Over`):** รันคำสั่งบรรทัดปัจจุบัน แล้วเลื่อนไปยังบรรทัดถัดไป (ไม่มุดเข้าไปในฟังก์ชัน)
- **`F11` (`Step Into`):** มุดเข้าไปดูการทำงานภายในฟังก์ชันย่อยที่ถูกเรียกในบรรทัดนั้น
- **`Shift + F11` (`Step Out`):** สั่งให้รันฟังก์ชันปัจจุบันให้เสร็จสิ้นแล้วกระโดดกลับออกมายังฟังก์ชันผู้เรียก
- **`Ctrl + Shift + F5` (`Restart`):** สั่งเริ่มการดีบักใหม่อีกครั้ง
- **`Shift + F5` (`Stop`):** สั่งยุติการดีบักทันที

### ขั้นตอนการทดลอง Debug ประจำปฏิบัติการ:
1. เปิดไฟล์ `main.py` ในโปรแกรม VS Code
2. วาง **Breakpoint (จุดหยุด)** โดยคลิกที่ขอบด้านซ้ายหน้าหมายเลขบรรทัดที่เป็นคำสั่ง:
   ```python
   choice = input("Enter choice (1-8): ").strip()
   ```
   (จะปรากฏจุดวงกลมสีแดง)
3. กดปุ่ม **`F5`** เพื่อเริ่มดีบัก (เลือกสภาพแวดล้อมเป็น **Python File**)
4. เมื่อโปรแกรมหยุดที่จุด Breakpoint ให้สังเกตหน้าต่างควบคุมด้านซ้าย:
   - **หน้าต่าง Variables:** ตรวจสอบค่าของตัวแปร `tasks` ในขณะนั้น
   - **หน้าต่าง Watch:** กดเครื่องหมาย `+` แล้วพิมพ์ `len(tasks)` เพื่อเฝ้าติดตามจำนวนงานแบบ Real-time
   - **หน้าต่าง Call Stack:** สังเกตลำดับการเรียกฟังก์ชันจากจุดเริ่มต้นมายังบรรทัดปัจจุบัน
5. กดปุ่ม **`F10`** เพื่อข้ามคำสั่ง หรือกด **`F11`** เพื่อตามเข้าไปดูการทำงานในไฟล์ `src/task_logic.py`

## 🐙 9. ขั้นตอนการใช้งาน Git และ GitHub (Git Workflow)

ให้นักศึกษาบันทึกประวัติการเปลี่ยนแปลงโค้ดลงใน Git อย่างสม่ำเสมอ โดยใช้คำสั่งดังนี้:

```bash
# 1. สร้าง Git Repository ภายในโฟลเดอร์ my-task-manager
git init

# 2. ตรวจสอบสถานะของไฟล์
git status

# 3. เตรียมไฟล์ขึ้น Staging Area (ระบบจะข้ามไฟล์ที่อยู่ใน .gitignore โดยอัตโนมัติ)
git add .

# 4. บันทึก Commit พร้อมข้อความอธิบายความเปลี่ยนแปลง
git commit -m "feat(cli): complete modular task manager with defensive error handling"

# 5. เชื่อมต่อกับ Repository บน GitHub ของนักศึกษา
git remote add origin https://github.com/YOUR_USERNAME/my-task-manager.git

# 6. ตั้งชื่อกิ่งหลักเป็น main และ Push ขึ้นสู่ระบบ
git branch -M main
git push -u origin main
```

### รูปแบบการตั้งชื่อ Commit Message ที่แนะนำ (Conventional Commits):
- `feat: ...` เมื่อมีการเพิ่มฟังก์ชันการทำงานใหม่ เช่น `feat: add task search functionality`
- `fix: ...` เมื่อมีการแก้ไขข้อผิดพลาดของโค้ด เช่น `fix: prevent crash on invalid task id input`
- `docs: ...` เมื่อมีการปรับปรุงหรือแก้ไขเอกสาร เช่น `docs: translate README into comprehensive Thai`
- `refactor: ...` เมื่อมีการปรับโครงสร้างโค้ดโดยไม่เปลี่ยนแปลงผลลัพธ์ภายนอก

## 🛠️ 12. สิ่งที่นักศึกษาต้องทำในโปรเจกต์นี้ (Step-by-Step Implementation Guide)

สำหรับนักศึกษาชั้นปีที่ 2 ในการพัฒนาโปรเจกต์นี้ ให้ปฏิบัติตามขั้นตอนอย่างเป็นลำดับดังนี้:

### ขั้นตอนที่ 1: จัดเตรียมสภาพแวดล้อมการพัฒนาและโครงสร้างโฟลเดอร์
1. เปิดโปรแกรม **Visual Studio Code** และเปิดโฟลเดอร์ `my-task-manager`
2. สร้าง Virtual Environment และเปิดใช้งาน (ถ้ามี):
   ```bash
   python -m venv venv
   # บน Windows:
   .\venv\Scripts\activate
   ```
3. สร้างโครงสร้างโฟลเดอร์ให้ตรงตามข้อกำหนด:
   - โฟลเดอร์ `src/` มีไฟล์ `__init__.py`, `task_data.py`, `task_logic.py`
   - โฟลเดอร์ `data/` สำหรับจัดเก็บ `tasks.json`
   - ไฟล์ `main.py` ที่ระดับ root
   - ไฟล์ `.gitignore` เพื่อละเว้นไฟล์ `__pycache__/`, `venv/`, `.vscode/`

### ขั้นตอนที่ 2: พัฒนาโมดูลจัดเก็บและโหลดข้อมูล (`src/task_data.py`)
1. กำหนด `TASKS_FILE` โดยใช้ `os.path` ให้สัมพันธ์กับตำแหน่งของโมดูลเสมอ
2. พัฒนาฟังก์ชัน `load_tasks()`:
   - ตรวจสอบว่ามีโฟลเดอร์ `data/` หรือไม่ หากไม่มีให้สร้างด้วย `os.makedirs(..., exist_ok=True)`
   - หากไฟล์ `tasks.json` ยังไม่มี ให้ส่งคืนลิสต์ว่าง `[]` โดยไม่แครช
   - ใช้บล็อก `try...except` ดักจับ `json.JSONDecodeError` และ `FileNotFoundError` หากไฟล์มีปัญหา ให้แจ้งเตือนและส่งคืน `[]` เพื่อความปลอดภัย
3. พัฒนาฟังก์ชัน `save_tasks(tasks)`:
   - บันทึกลิสต์ `tasks` ลงในไฟล์ `tasks.json` ด้วย `json.dump(tasks, f, indent=4, ensure_ascii=False)`

### ขั้นตอนที่ 3: พัฒนาตรรกะระบบจัดการงาน (`src/task_logic.py`)
1. สร้างฟังก์ชัน `get_next_task_id(tasks)`: คำนวณหาค่า ID สูงสุดแล้วบวก 1 หากลิสต์ว่างให้เริ่มต้นที่ 1
2. สร้างฟังก์ชัน `add_task(tasks, description, priority='Medium')`:
   - ตรวจสอบข้อมูล (Validation): หาก `description` เป็นช่องว่าง ให้แสดงข้อความเตือนและไม่เพิ่มงาน
   - กำหนดสถานะเริ่มต้น `completed: False`
3. สร้างฟังก์ชัน `list_tasks(tasks, filter_status=None)`:
   - แสดงตารางรายการงานที่มีคอลัมน์ ID, Description, Status, Priority
   - หากไม่มีงาน ให้แสดงข้อความ `"No tasks found."`
4. สร้างฟังก์ชัน `complete_task(tasks, task_id)`:
   - ค้นหางานตาม `id` และเปลี่ยนสถานะเป็น `True` หากไม่พบ ให้แจ้ง Error
5. สร้างฟังก์ชัน `delete_task(tasks, task_id)`:
   - ลบงานที่ตรงกับ `id` ออกจากลิสต์ หากไม่พบ ให้แจ้ง Error
6. *(ส่วนขยายปี 2)* สร้างฟังก์ชัน `search_tasks(tasks, keyword)`:
   - ค้นหางานที่คำอธิบายตรงกับคำค้นหา (Case-insensitive)

### ขั้นตอนที่ 4: พัฒนาส่วนติดต่อผู้ใช้ CLI (`main.py`)
1. สร้าง Interactive Menu Loop ด้วย `while True`
2. แสดงตัวเลือกเมนู 1 ถึง 8 ให้ผู้ใช้เลือกอย่างชัดเจน
3. ใช้การเขียนโปรแกรมเชิงป้องกัน (Defensive Programming):
   - ใช้ `try...except ValueError` เมื่อรับค่า Task ID เพื่อป้องกันโปรแกรม Crash เมื่อผู้ใช้พิมพ์ตัวอักษรแทนตัวเลข
   - เมื่อผู้ใช้เลือก Exit หรือกด `Ctrl+C` (`KeyboardInterrupt`) ให้บันทึกข้อมูล `save_tasks(tasks)` เสมอก่อนออกจากโปรแกรม

### ขั้นตอนที่ 5: ฝึกฝนการดีบักด้วย VS Code Debugger
1. วาง Breakpoint ที่บรรทัดรับ Input และบรรทัดบันทึกไฟล์ใน `main.py`
2. กด `F5` เพื่อเริ่ม Debug และใช้ `F10` (Step Over) / `F11` (Step Into)
3. สังเกตตัวแปรในหน้าต่าง Variables และ Call Stack เพื่อทำความเข้าใจการไหลของข้อมูลในหน่วยความจำ

### ขั้นตอนที่ 6: การจัดเก็บเวอร์ชันด้วย Git และ Commit สื่อความหมาย
1. เริ่มต้น Git Repository ด้วยคำสั่ง `git init`
2. ทำการ Commit งานแยกตามงานย่อยอย่างน้อย 3-5 Commits เช่น:
   - `feat(data): implement json loading and saving with error handling`
   - `feat(logic): implement task CRUD operations and search`
   - `feat(cli): build interactive menu with defensive input validation`
   - `docs: update comprehensive README documentation`
